The Business Problem

Salla's customer experience leadership operated with monthly telephony export logs across disparate sheets (Dec 2023, Jan 2024, Feb 2024). This fragmentation prevented longitudinal workforce monitoring, masked queue congestion patterns, and obscured a massive 28.4% demand forecasting deviation that caused severe shift over-allocation and wasted budget.

1,744,885 Total Calls Offered
98.7% Answer Rate (1.72M)

Phase 1: Power Query ETL Data Pipeline

01
Multi-Source Consolidation: Connected to three monthly Excel workbooks containing 90 days of telephony logs. Executed Table.Combine / Append Queries as New into a single unified Dataset table.
02
Type Enforcement & Cleaning: Re-casted call timestamps into strict ISO DateTime, converted call durations into total integer seconds, eliminated phantom header rows, and cleaned agent IDs.
03
Categorical Normalization: Normalized telephony status tags (Answered, Abandoned, Overflow) and engineered binary flag columns (IsAnswered, IsWithinSLA) to boost VertiPaq engine compression.

Preventing the "Average-of-Averages" Mathematical Fallacy

In high-volume telephony analytics, computing AVERAGE(Dataset[ASA]) across daily records produces mathematically distorted figures because a morning peak with 50,000 calls would receive identical weight to a midnight hour with only 200 calls. All KPIs were engineered as Weighted Volume Averages:

Weighted Average Speed to Answer (ASA) DAX 
Weighted ASA (Seconds) = 
DIVIDE(
    SUM(Dataset[Answer_Speed_Sec]),
    CALCULATE(
        COUNTROWS(Dataset),
        Dataset[Status] = "Answered"
    ),
    0
)
• Calculated benchmark: 14.3 Seconds across 1,721,842 answered calls.
Service Level Agreement (SLA % ≤ 20s) DAX 
SLA Compliance % = 
VAR HandledCalls = 
    CALCULATE(COUNTROWS(Dataset), Dataset[Status] = "Answered")
VAR CallsWithinThreshold = 
    CALCULATE(
        COUNTROWS(Dataset), 
        Dataset[Status] = "Answered",
        Dataset[Answer_Speed_Sec] <= 20
    )
RETURN
DIVIDE(CallsWithinThreshold, HandledCalls, 0)
• Enterprise Target: ≥ 90.0% | Actual Audited: 91.1%
Forecasting Variance & Error Rate DAX 
Forecast Variance (Calls) = 
[Total Offered Calls] - [Forecasted Demand Calls]

Forecast Variance % = 
DIVIDE([Forecast Variance (Calls)], [Forecasted Demand Calls], 0)
• Actual Offered: 1,744,885 vs Forecast: 2,437,071 → Variance: -692,186 calls (-28.4%).
Call Center Answer Rate % DAX 
Answer Rate % = 
VAR TotalOffered = COUNTROWS(Dataset)
VAR TotalAnswered = 
    CALCULATE(COUNTROWS(Dataset), Dataset[Status] = "Answered")
RETURN
DIVIDE(TotalAnswered, TotalOffered, 0)
• Result: 98.7% (Abandonment rate kept exceptionally low at 1.3%).
